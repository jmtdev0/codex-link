# Adaptador experimental para Sites

`worker/index.js` implementa el contrato de `../RELAY_API.md` usando APIs web estándar y la binding D1 `DB` declarada en `.openai/hosting.json`. `npm run build` incluye el Worker, el manifiesto y la migración SQL; `npm run validate` comprueba el artefacto. Exige `CODEX_LINK_ACCESS_TOKEN` como secreto de entorno; no lleva claves ni credenciales en el código. El plugin cifra el contenido antes de llamar al Worker.

La base guarda IDs de sala/participante y el sobre cifrado JSON, nunca el secreto de invitación ni texto plano. Cada sobre deja de entregarse tras cinco minutos y se borra al recibir un ACK; las salas caducan a los 30 minutos y al cerrarlas se borra la cola. Las filas caducadas se purgan oportunistamente cuando llega tráfico, no mediante un cron, así que una sala inactiva puede dejar residuos lógicos hasta la siguiente petición. La URL remota del plugin exige HTTPS y el token independiente.

**Límite de retención:** D1 Time Travel puede conservar estados recuperables hasta 7 días en Workers Free o 30 días en Workers Paid. Por tanto, un ACK o TTL borra la fila actual, pero no garantiza que sus bytes sean irrecuperables en copias históricas durante ese plazo. El historial contiene solo ciphertext y metadatos; el relé no conoce la clave E2E. Consulta la [documentación de Cloudflare D1](https://developers.cloudflare.com/d1/reference/time-travel/) y confirma la política actual de tu cuenta.

El Site debe mantenerse privado. El manifiesto `.openai/hosting.json` contiene el ID de cada despliegue; el archivo de ejemplo permite crear uno nuevo, pero no incluye una identidad de Site. El acceso desde clientes no interactivos se hará con el token de servicio de Sites en `CODEX_LINK_SITES_BYPASS_TOKEN`; el plugin lo envía como `OAI-Sites-Authorization` únicamente al origen exacto configurado. `CODEX_LINK_ACCESS_TOKEN` es un secreto de aplicación separado que también debe configurarse en el entorno del Site y en ambos clientes. Ninguno de esos valores debe añadirse al repositorio.

**La ruta completa entre dos ordenadores aún no está validada.** Las pruebas `../tests/site-worker.test.mjs` ejecutan la migración y el Worker contra SQLite real, y demuestran que instancias independientes comparten la sala y entregan ciphertext mediante la misma base. Antes de enviar información sensible, comprueba la ruta desde dos ordenadores y cuentas separados.
